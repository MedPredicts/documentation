## 1. Предмет оценки и исходные условия

Тема проекта — «Разработка интеллектуальной системы прогнозирования медицинских показателей на основе нейронных сетей». Отдельно проверяются три вещи: исследовательское качество моделей, корректность технической интеграции и понятность пользовательского сценария. Фиксированный демонстрационный ответ 134,2 не входит в метрики модели, время вывода или клинические заключения.

Основа: [спецификация требований](06_Спецификация_требований.md), [архитектура](07_Архитектура_и_диаграммы.md), [обзор литературы](03_Обзор_литературы.md), [сравнение систем](04_Сравнение_существующих_систем.md) и требования университета. Статус старых диаграмм сверяется отдельно; их наличие не доказывает готовность будущих модулей. Научные руководства из обзора — TRIPOD+AI, PROBAST+AI и руководство по внешней валидации. Следование этому плану не означает, что получено медицинское одобрение.

Для каждого нового эксперимента до обучения Али фиксирует паспорт набора данных: источник и версия, разрешение / лицензия, единица наблюдения, включения и исключения, целевая переменная и её момент времени, признаки, действительно доступные на момент оценки, единицы, пропуски и границы популяции. Руководитель рассматривает постановку. Оралхан и Санат согласуют, что схема данных соответствует API и экрану. Для M3 дополнительно нужен контракт последовательности; текущие поля number / select его не заменяют.

M1. Проверить параметры загрузчика. Предпочтительны исходные признаки (scaled=False, если это поддерживает зафиксированная версия), а стандартизацию подбирать внутри Pipeline только на обучающей части / складке CV. Глобально нормированный учебный массив нельзя молча использовать как доказательство отсутствия утечки при предобработке. Клинические единицы не приписываются признакам, которые уже нормированы.

M2. В выполненном v2 target — среднее минимум двух валидных измерений одного визита; это оценка текущего измеряемого САД, не прогноз будущего давления. Для нового независимого эксперимента до обращения к test фиксируются допустимые измерения и агрегирование по кодбуку выбранного цикла. Служебные коды отказа / «не измерено» не превращаются в реальные числа. Производные целевого АД не используются как вход. Нужно указать, чем является исследование: оценкой качества прогнозов внутри выборки или популяционным анализом: выводы о всём населении США требуют отдельной обработки сложного дизайна NHANES и весов. Национальная применимость для Казахстана не предполагается.

M3. Записи глюкозы в реанимации могут быть нерегулярными и отличаются от CGM. Нужны проверки плотности измерений, единиц, качества меток времени, минимальной истории и определения точки прогноза. Нельзя интерполировать через границу теста и использовать более позднее измерение для заполнения прошлого. Перенос на нового субъекта следует отделять от персонального прогноза; эти режимы нельзя смешивать в одной оценке. Если данных недостаточно, модуль остаётся нереализованным, а не получает произвольный горизонт.

## 3. Очистка и обучение

До разбиения допускаются только формат, единицы и детерминированное удаление явных дубликатов по заранее описанному правилу. Обучаемые преобразования (импутация, масштабирование, отбор признаков, кодирование категорий и настройка гиперпараметров) выполняются только внутри train / CV. Правила исключения опираются на словарь данных и постановку, а не на желание улучшить тестовую метрику. Схема исключений и число пропусков по частям публикуются.

Простой базовый метод получает те же доступные признаки и ту же тестовую выборку. Для будущих M1 / M3 поиск по архитектуре, регуляризации, скорости обучения, размеру батча и ранней остановке по validation ограничивается заранее. Раннее предложение seed 17, 42 и 2026 не описывает уже выполненный M2: для него фактические seeds — 2026 / 2027 / 2028, представитель выбранной конфигурации — 2026. Для новых экспериментов итоговый список и бюджет фиксируются до запуска. Лучший seed на тестовой выборке не выбирается. Для небольших данных вместо расширения пространства поиска рассматривается повторная вложенная CV; итоговая схема должна быть одной схемой, записанной заранее.

Сохраняются версии библиотек и среды, конфигурация оборудования, seed, индексы / правило разбиения, предобработка только на train, параметры обучения, критерий остановки, артефакт и его SHA-256. Ограниченные данные не помещаются в публичный Git: хранится допустимая процедура их получения и проверяемый манифест без идентификаторов пациентов.

## 4. Метрики и интерпретация

Для n наблюдений и ошибок e_i = y_hat_i − y_i: MAE = Σ|e_i| / n; RMSE = √(Σe_i² / n). MAE читается как средняя абсолютная ошибка; RMSE подчёркивает большие отклонения. Обе метрики сохраняют единицы цели, поэтому их нельзя сравнивать между шкалой Diabetes, мм рт. ст. и глюкозой как общий рейтинг. R² может быть дополнением и не заменяет ошибки в исходных единицах. «Точность 95%» для непрерывного исхода без определения не используется.

Отчёт содержит базовый метод, нейронную сеть, разницу ошибок на одинаковых наблюдениях и неопределённость. Для независимых пациентов допустим парный бутстреп тестовых наблюдений; для временных рядов — повторная выборка субъектов / блоков с сохранением зависимости. Предлагаются 1 000 повторов бутстрепа и 95% интервалы, если позволяет эффективный размер выборки. Метод и число повторов согласуются до итоговой оценки; интервал не обещает переноса на другую популяцию.

Проверяются распределение остатков, крупные ошибки, зависимость от диапазона истинного исхода, полнота данных и подгруппы достаточного размера. Для M3 дополнительно различаются участки роста и падения, запаздывание прогноза и дальние горизонты. Выводов по подгруппам на основе единичных случаев не делается; числа и границы показываются вместе. Объяснения важности признаков, если они есть, описывают поведение модели и не являются причинным объяснением болезни.

Критерий завершения исследования: протокол воспроизводится, базовый метод и сеть оценены честно, границы и отрицательные результаты сохранены. Критерий заявления об улучшении: заранее выбранная основная метрика и её неопределённость подтверждают заявленный эффект на независимых данных. Если улучшения нет, исследовательскую работу всё равно можно завершить, но утверждение о превосходстве исключается. Клинические пороги качества без предметного обоснования не задаются.

## 6. Время ответа и воспроизводимость измерений

Для NFR-09 описываются CPU / RAM / ОС, Java / Python / среда выполнения, модель и её размер, холодный / тёплый режим, источник и сеть, параллелизм, объём данных и границы таймера. Измеряются минимум 30 успешных тёплых POST-запросов от отправки до полностью прочитанного и проверенного ответа; холодные вызовы считаются отдельно. Публикуются p50 / p95, число ошибок / тайм-аутов и общее число попыток. Неудачные запросы не исключаются из знаменателя доли ошибок. Серверная предобработка / вывод измеряются отдельно от задержки браузера.

Бюджет B для p95 утверждается до приёмочного прогона после пилота и после определения среды; его числовое значение — PENDING. Предлагаемый критерий: p95 ≤ B и отсутствие необъяснённых ошибок в согласованном наборе. Текущий тайм-аут 15 000 мс защищает UI; это не SLA и не измеренное время. Задержка демо включает искусственную паузу и не характеризует модель. Пропускная способность под нагрузкой заявляется только при отдельном плане параллелизма и длительности.

## 7. Удобство использования и понимание

Участники — реальные представители согласованной аудитории из плана исследования пользователей, после получения согласия. Пилот из 3–5 человек даёт качественные свидетельства, а не популяционную статистику. Тестируется существующий интерфейс с вымышленными значениями; несуществующие модули обсуждаются только как концепция.

## 9. Артефакты и решение о приёмке

Для каждого будущего запуска хранятся идентификатор эксперимента, дата, исполнитель, код / артефакт / среда, манифест входных данных, метод разбиения, таблица метрик, ошибки и решение с границами. Шаблон результата: «не запускалось / выполнено / воспроизведено / принято с ограничениями / отклонено», без заранее заполненных чисел. Али отвечает за отчёт по модели, Оралхан — за интеграцию и серверные измерения, Санат — за UI и сценарии; руководитель оценивает научную достаточность. Технический M2-путь имеет сохранённые подтверждения. Научная приёмка, независимое воспроизведение, внешняя / казахстанская оценка и production-приёмка остаются отдельными открытыми решениями; публикация кода их не заменяет.

## 10. Предлагаемая независимая оценка после сравнения аналогов

Основание — [сравнение систем](04_Сравнение_существующих_систем.md) от 22 октября. Следующие работы предложены для рассмотрения команды и руководителя; данных, участников и результатов этой редакцией не добавлено.

1. **Практическая полезность.** Проверить, в какой учебной / исследовательской задаче оценка САД по возрасту, полу, ИМТ, холестерину и глюкозе натощак полезна. Сопоставить трудозатраты лабораторного ввода с прямым измерением тонометром; не считать положительное мнение в интервью доказательством выигрыша.
2. **Новый независимый набор.** До доступа к результатам зафиксировать модель / SHA-256, целевую популяцию, источник и права на данные, сопоставимость измерений, правила пропусков и исключений, основную метрику и анализ групп. Данные нового участника не должны попадать в настройку модели или preprocessing.
3. **Отдельный план для Казахстана.** Определить местного исследовательского партнёра, необходимый порядок согласия / доступа и применимые условия исследования. Пока набора нет, статус — «не выполнено»; американская временная проверка или региональная группа HeartScore не заменяет казахстанскую когорту.
4. **Ошибка и смещение.** Отчёт включает weighted / unweighted показатели в соответствии с дизайном данных, MAE / RMSE, signed bias, размеры групп и распределение ошибок; отдельно — случаи высокого фактического САД, возраст и пол при достаточном числе наблюдений. Критерии качества устанавливаются до итоговой оценки с предметным обоснованием, а не назначаются по уже увиденному test.
5. **Неопределённость.** Интервал средней метрики не является индивидуальным прогнозным интервалом. Если команда выберет отдельный метод индивидуальной неопределённости, его покрытие и ширина проверяются на независимых данных; произвольный confidence или «±MAE» не добавляется.
6. **Полный языковой сценарий.** Сохранить T08 для Accept-Language и дополнительно проверить metadata-подписи, единицы, результат, ошибки и PDF на RU / KK / EN. Изменение заголовка запросов само по себе не локализует все серверные тексты.

История, импорт анализов, устройства, напоминания и кабинет врача оцениваются после подтверждения потребности и определения правил данных. Они не становятся обязательными критериями текущего M2 только по наличию у аналогов.
